# Architecture decision records

Recorded during the autonomous rebuild session. Each entry states the decision actually
taken and the assumption behind it, because the author was asleep and could not be asked.

---

## ADR-0001: Postgres runs from `pgserver`, not Docker, in this environment

**Status:** accepted

**Context.** The brief locks the store to Postgres 16 with pgvector via Docker Compose.
The session sandbox has no Docker daemon, no root and no package manager access, so
`docker compose up` cannot be executed here.

**Options.** (1) Declare Phase 1 blocked and run nothing. (2) Substitute SQLite plus a
numpy brute-force index for local work. (3) Find a way to run a real PostgreSQL 16 with
pgvector without Docker.

**Decision.** Option 3. `pgserver` on PyPI ships a self-contained PostgreSQL 16.2 build
with pgvector 0.6.2 and starts it against a data directory owned by the current user. The
application talks to it over a normal DSN and knows nothing about how the server started.
`infra/docker-compose.yml` and the Dockerfiles are still authored and are the documented
production path; they are simply unverified in this session.

**Consequence.** No substitution of the locked technology. The compose path is marked
unverified in `docs/HANDOFF.md` rather than claimed as working.

## ADR-0002: Alembic owns the schema, and the vector index is HNSW

**Status:** accepted

**Decision.** Alembic owns the schema, hand-written rather than autogenerated so that
the extension, the generated `tsvector` column and both index types are reviewable.
Embeddings live in a `vector(384)` column with an HNSW index using `vector_cosine_ops`.
A provider whose `dim` differs from the column is rejected at startup rather than
silently truncated.

**Assumption made while the author was asleep.** HNSW over IVFFlat, because the corpus is
small enough that build time is irrelevant and HNSW needs no training step and no tuned
list count.

## ADR-0003: the default embedding provider in this session is not `bge-small-en-v1.5`

**Status:** accepted, and the most consequential compromise in the session

**Context.** The brief fixes `LocalEmbeddings` to `BAAI/bge-small-en-v1.5` via
sentence-transformers and makes it the default for all evals, CI and tests, so everything
runs with zero API keys. Every huggingface.co host is blocked by the egress proxy in this
sandbox. The verbatim probe result:

```
$ curl -sS -m 8 https://huggingface.co
curl: (56) Received HTTP code 403 from proxy after CONNECT
```

The same applies to `cdn-lfs.huggingface.co` and to `hf-mirror.com`, so no mirror helps.

**Options.** (1) Ship `StubEmbeddings` and mark every eval blocked. (2) Fit a real,
deterministic embedding model on the corpus with no network: TF-IDF over word and
character n-grams reduced to 384 dimensions by truncated SVD, which is classical latent
semantic indexing. (3) Fabricate numbers. Not an option.

**Decision.** Option 2, named `LsaEmbeddings`, as the default provider for eval and CI in
this session. `SentenceTransformerEmbeddings` implements the same interface and is the
intended default the moment weights are reachable; selecting it here fails loudly with
the download error rather than falling back silently. `StubEmbeddings` exists and is used
only by unit tests that care about plumbing, and the eval runner refuses to write metrics
produced with it.

**Consequence, stated plainly.** The absolute retrieval numbers in `eval/results/` are the
numbers for an LSA dense arm, not for a modern sentence encoder. They are real
measurements of a real system, reproducible by one command, but they are a floor rather
than a claim about what bge-small would score. Every table that reports them names the
provider. Re-running the identical sweep with
`CHAINLENS_EMBEDDING_PROVIDER=sentence-transformers` on a networked machine is a single
environment variable, and that is written into `docs/HANDOFF.md`.

## ADR-0004: the cross-encoder reranker is implemented but not measured

**Status:** accepted

**Context.** `BAAI/bge-reranker-base` is on Hugging Face and unreachable for the same
reason as ADR-0003. A reranker cannot be approximated by a lexical heuristic without the
resulting number being a lie about what "cross-encoder rerank" means.

**Decision.** `CrossEncoderReranker` is written against the `Reranker` interface and wired
into both the retrieval pipeline and the ablation grid. In this environment the three
`rrf_rerank` cells are recorded in `eval/results/` with `status: "blocked"` and the
verbatim error, and every table renders them as a dash with a footnote. The pipeline
degrades to fusion-only when the reranker is unavailable and records that fact in the
trace, which is also the Phase 7 graceful-degradation requirement, so the fallback path is
real rather than hypothetical.

## ADR-0005: generation-side evaluation is blocked, retrieval-side evaluation is not

**Status:** accepted

**Context.** Groundedness and answer correctness in the brief are LLM-judged. The
generation host is blocked and no key is present.

**Decision.** The prompt, the streaming client with a real client-level timeout, the
runtime groundedness guard and the result schema are all implemented and committed,
because they are the part a reviewer should be able to read and criticise. No groundedness
or correctness number is written anywhere. Retrieval metrics, latency and index statistics
are unaffected and fully measured.

## ADR-0006: k is a reporting depth, not a grid axis

**Status:** accepted

**Context.** The brief lists `k` in {3, 6, 10} as an ablation axis alongside chunking and
retrieval strategy. Retrieving to depth 10 and truncating to 3 produces exactly the same
ranking as retrieving to depth 3, for every strategy in the grid.

**Decision.** One run per (chunking, retrieval) cell retrieves to max(k) and scores every k
from the same ranking. Writing three near-identical files per cell would invite a reader to
assume three independent measurements happened. All three k values are reported in every
result file and in every table.

## ADR-0007: frontend precedence when the design skills disagree

**Status:** accepted

**Context.** The brief sets a precedence table: Impeccable in product mode decides what the
interface looks like; the local skills decide how it is built; `motion-discipline` owns
motion; `async-states` owns data states; `accessibility-audit` owns the audit.

**Decision.** That precedence is adopted verbatim. `npx impeccable install` was not run in
this session, so under the brief's own fallback clause the local `frontend-design` skill
takes the aesthetic-authority seat and the taste process in `docs/taste-pass.md` is
performed either way. Regardless of which authority produced a value, no raw hex and no
palette utility class reaches component markup: everything resolves through the semantic
token layer, so a re-skin stays a variable swap.

**Conflict actually hit, and its resolution.** The concept direction calls for hairline
rules and boxed fields with tiny letterspaced labels, which pushes toward very low
contrast borders; `accessibility-audit` requires 3:1 for meaningful non-text boundaries.
Resolved in favour of accessibility, per the precedence table: the rule token is set at
the lightest value that still measures 3:1 against the page ground, and the computed ratio
is recorded in `docs/taste-pass.md` rather than eyeballed.

## ADR-0008: the repository is mirrored out of an ephemeral sandbox

**Status:** accepted, and it is an environment workaround rather than a design choice

**Context.** Partway through the session the sandbox discarded `/tmp` between commands and
took the working tree with it. The connected folder persists but does not permit `unlink`,
which permanently breaks git's index lock inside it, so git cannot run there.

**Decision.** The repository lives in `/tmp/chainlens` with full git, and
`scripts/mirror.sh` copies the working tree into the connected folder after each
checkpoint, together with `chainlens-rebuild-v2.bundle` carrying the real branch history.
Recovering the history on a normal machine is
`git fetch chainlens-rebuild-v2.bundle rebuild/v2`.

**Consequence.** The connected folder also still contains the v1 files, because they
cannot be deleted from that side. Checking out `rebuild/v2` on a machine with normal
filesystem permissions removes them. This is recorded in `docs/HANDOFF.md`.
